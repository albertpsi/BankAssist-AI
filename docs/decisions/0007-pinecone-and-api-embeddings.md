# ADR-0007 — Pinecone and API embeddings replace ChromaDB and local sentence-transformers

**Status:** Accepted 2026-08-03 (Gate 3, alongside the Lab 2 implementation plan)
**Date:** 2026-08-03
**Amends:** [ADR-0001](0001-technology-stack.md), `docs/architecture/technology-stack.md` §2

## Context

The approved technology stack chose **ChromaDB** as the vector store and
**`sentence-transformers` `all-MiniLM-L6-v2`** for embeddings. Both were selected for the
same reason: they were already installed, run locally at zero marginal cost, need no
account, and keep the whole retrieval path offline and deterministic. That reasoning was
sound and is unchanged.

The Lab 2 brief mandates **Pinecone** and **`text-embedding-3-small`**, and explicitly
forbids `sentence-transformers`. This is not a technical preference we are free to
re-litigate — it is the lab requirement being graded, and demonstrating a managed vector
database is part of what Lab 2 is teaching. The requirement therefore overrides the stack
decision.

Two constraints were live at the time of writing:

- `PINECONE_API_KEY` is **not** set on this machine and no Pinecone account is configured.
  `OPENAI_API_KEY` is set.
- The project's "local-first" architecture principle (CLAUDE.md §3) says the vector store
  runs locally. That principle is now partly false and needs amending rather than quietly
  contradicting.

## Decision

For Lab 2 and every lab after it, the vector store is **Pinecone** (serverless, namespace
`bank-policies`) and embeddings are generated by the OpenAI **`text-embedding-3-small`**
model at 1536 dimensions. ChromaDB and `sentence-transformers` are removed from the stack
and are not installed.

Both dependencies sit behind narrow first-party interfaces — `VectorStore` and `Embedder`
in `src/bankassist/rag/` — each with an in-repo test double, so the entire test suite runs
with no account, no network, and no cost. Only the ingestion script and a live query touch
the real services.

CLAUDE.md's "local-first" principle is amended to: **retrieval mechanics are inspectable
and the test suite is offline; the vector store and the embedding model are hosted.**

## Alternatives considered

**Keep ChromaDB and MiniLM, and note the deviation in the write-up.** The technically
cheaper option: zero cost, offline tests, no new account. Rejected because Lab 2 is graded
on demonstrating a managed vector database and a hosted embedding model, and a lab
completed with a substitute stack is a lab not completed.

**Pinecone for the vector store, but keep MiniLM embeddings locally.** Halves the change
and keeps embedding free. Rejected: the brief names `text-embedding-3-small` and explicitly
forbids `sentence-transformers`. It would also give a 384-dimension index that a later
switch to API embeddings could not reuse — the index dimension is fixed at creation.

**Run both stores behind the `VectorStore` interface and make them switchable.** Superficially
attractive — it would preserve the offline path. Rejected as scope creep under the standing
discipline: a second production implementation that no lab objective requires, plus a
migration story, plus double the ingestion paths to keep working. The test double already
provides everything the offline requirement actually needs.

**Defer the decision and start with Chroma, migrating in Lab 3.** Rejected: the migration
would land in the middle of the lab with the highest retrieval complexity, and re-embedding
the corpus at a different dimension means rebuilding the index anyway. Changing now costs
one afternoon; changing in Lab 3 costs the same afternoon plus the risk.

## Consequences

**Makes easy.** Lab 2 satisfies its brief exactly. Retrieval quality improves —
`text-embedding-3-small` (1536-d) meaningfully outperforms MiniLM (384-d) on the kind of
paraphrased policy question this corpus will be asked. The Pinecone console gives a
first-class screenshot for the "index populated" evidence that a local Chroma directory
could not. `torch` and its ~2.5 GB dependency tree never need installing.

**Makes hard.** The system now needs a second credential and network access to answer any
question — a demo with no internet is a demo that cannot retrieve. Embedding becomes a paid,
rate-limited, non-deterministic-latency API call rather than a free local one. Two hosted
dependencies now sit on the critical path instead of one.

**Accepted costs.**

- **Money.** ~250 chunks ≈ 200k tokens ≈ well under one cent per full ingestion, plus one
  embedding per query. Immaterial at lab scale; the price table entry for
  `text-embedding-3-small` must still be verified before any Lab 7 cost figure is quoted.
- **Lab 3.** Cross-encoder reranking was specified as a local `sentence-transformers`
  `CrossEncoder`. That library is now forbidden, so Lab 3 must choose a different reranking
  approach. **This is a real open item, flagged here rather than discovered later.**
- **Lab 7.** The semantic cache was designed to reuse the already-loaded MiniLM model at
  zero marginal cost. It will now embed cache probes through the API instead — still cheap,
  but a paid call on the lookup path, which slightly weakens the cost-saving arithmetic that
  lab is meant to demonstrate. To be quantified honestly there rather than assumed away.
- **Latency.** Ingestion and every query gain a network round trip that was previously
  in-process.

**Test obligation.** No test may call Pinecone or the OpenAI embeddings API. The `Embedder`
and `VectorStore` doubles are what make that hold, and a test asserting the suite runs
without credentials is part of Lab 2's definition of done.

## Revisit when

The lab sequence is complete and the system is being considered for anything beyond
teaching; the corpus grows past what a serverless free tier serves comfortably; a
requirement appears for fully offline operation; or Lab 3's reranking choice forces a
reconsideration of the embedding provider.
